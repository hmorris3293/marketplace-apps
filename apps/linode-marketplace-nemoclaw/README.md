# Akamai Nemoclaw Quick Deploy App

NemoClaw is an NVIDIA AI agent platform that runs locally and exposes a web dashboard through an authenticated NGINX reverse proxy. This deployment uses secure defaults and installs Docker, OpenShell, Node.js, and the NemoClaw CLI during provisioning.

## Software Included

| Software | Version | Description |
| :--- | :--- | :--- |
| NemoClaw | `lkg` (default) | AI agent orchestrator installed from the NVIDIA GitHub repository via npm |
| OpenShell | Latest | NVIDIA OpenShell CLI binary matching system architecture |
| Docker Engine | Ubuntu package | Docker runtime configured with host cgroup namespace mode |
| Nginx | `1.24` | Web server and reverse proxy handling SSL termination. |
| Node.js | `22.22.1` | JavaScript runtime environment |

**Supported Distributions:**
- Ubuntu 24.04 LTS

# Post Deployment

When the Nemoclaw Quick Deploy App has finished installing, NemoClaw has been installed from a pinned git ref (`lkg` by default) using `npm install -g`. Here are some notes about the deployment:

- Nemoclaw runs as a limited user on the instance called `nemoclaw`. The `nemoclaw` user has limited scope defined in `/etc/sudoer.d/nemoclaw`
- Nginx runs as the web server and reverse proxy to the nemoclaw gateway. SSL/TLS terminiation is done by Nginx and Let's Encrypt certificates are installed.
- A sudo user is created on the instance for system administrative purposes. In this example, we are using `admin`.
- Dashboard access is protected by NGINX basic auth (`htpasswd`) and NemoClaw token authentication.
- You can control the installer source ref/tag at deployment time with the `nemoclaw_install_ref` UDF.
- A first-login onboarding script is installed at `/etc/profile.d/nemoclaw-setup.sh` and runs `nemoclaw onboard` once per interactive user.

## Accessing Nemoclaw Dashboard

After deployment, access the dashboard from the configured domain (or default rDNS hostname). You can view the rDNS value from the [Linode's Network](https://techdocs.akamai.com/cloud-computing/docs/configure-rdns-reverse-dns-on-a-compute-instance#setting-reverse-dns) tab.

In this example, we'll use the value of `172-233-177-79.ip.linodeusercontent.com`.

To authenticate to the dashboard you need two methods of authentication:
1. Dashboard token:
    - The deployment writes a dashboard token hint into `/home/<sudo-user>/.credentials`.
    - If needed, regenerate the URL by running `su - nemoclaw -c "nemoclaw dashboard --no-open"`.
2. Nginx Htpasswd:
    - Grab the `Htpassword` password and `Htpasswd username` user from `/home/<sudo-user>/.credentials`.

At this point you have everything you need to access the dashboard. For example:
`https://172-233-177-79.ip.linodeusercontent.com/#token=a0764fb`

When you access the web page you will be prompted for the HTPASSWD details. Once you enter the credentials you will be able to proceed to the dashboard.
